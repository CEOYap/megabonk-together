# Test Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `BotMode` switch that turns a second local Megabonk copy into a client that joins the owner's lobby, plays the whole run invincibly near the owner, uses nearby chests and shrines, picks rewards at random, and revives the owner.

**Architecture:** One injected `MonoBehaviour` (`BotController`) holds a small state machine and decides what the bot wants each frame. It never calls sync services or sends messages: it writes its intent into a static `BotInput` (a movement vector and one-frame button presses), and thin Harmony patches on `MyInputManager` feed that intent to the game as if a controller produced it. Invincibility is one guarded prefix. Everything is behind `ModConfig.BotMode` and the netplay-session guard.

**Tech Stack:** C# / BepInEx 6 IL2CPP / HarmonyX / Il2CppInterop, existing plugin project `src/plugin`.

**Spec:** `docs/superpowers/specs/2026-10-19-test-bot-design.md`

## Global Constraints

- Every bot code path is a no-op unless `ModConfig.BotMode.Value` is true; every Harmony patch also opens with `HasNetplaySessionStarted()` where it touches gameplay. Singleplayer and switch-off sessions must be byte-for-byte unchanged in behaviour.
- **No wire change:** no new `IGameNetworkMessage`, no new field, no `[MemoryPackUnion]` edit.
- The bot drives the game only through input (`MyInputManager`) and the game's own UI/interact methods. It never calls `SynchronizationService`, `INetTransport` or `IUdpClientService`.
- Bot copy runs with `UseSteamTransport = false`, `Application.runInBackground = true`, `Application.targetFrameRate = 30`.
- `[bot]` status line every `Tunables.DIAGNOSTIC_REPORT_INTERVAL_SECONDS` (10 s); no other per-frame logging.
- Decompile (`scripts/re/decompile_headless.py`, VAs from `megabonk-re/build-21750826/dump.cs`, never RVAs) before relying on any game method's behaviour; mark what is still inferred **UNVERIFIED** in the commit.
- Avoid hooking methods with `out`/`ref` value-type parameters (their trampoline broke in OB-26).
- Casting a `Window` uses `Helpers.WindowCast`; other game casts use `GetComponent<T>()`, never C# `as` on a proxy.
- One logical change per commit; commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Verification model.** This repository has no test suite and the behaviour is in-game, so each task's "test" is: the build passes (`dotnet build MegabonkTogether.sln -c Debug`, 0 errors), then a stated in-game check whose pass condition is a specific log line or visible behaviour on the two-copy setup from Task 2. Where a task contains pure logic (steering, target choice), it is written as a static method with no Unity calls besides `Vector3` math, so a reviewer can check it by reading.

## Review Focus

1. **The bot copy loses focus** (the owner is always in their own window). Expect: the bot keeps moving and picking. Test owned by Task 1 (first in-game check is with the bot window unfocused).
2. **Stage transitions and loading screens.** Expect: the bot drops its target, waits for its player to exist again, and resumes; it never acts on a destroyed object. Test owned by Task 5 (play through one portal).
3. **The game is paused by an encounter window, its own or the owner's** (shared experience). Expect: no movement input is consumed while paused, the bot's own window still gets a pick, and the barrier releases for both. Test owned by Task 6.
4. **The owner leaves or disconnects mid-run.** Expect: the bot stops steering (no owner to follow), logs it once, and does not throw every frame. Test owned by Task 5.
5. **The bot falls out of the map or into a pit** (invincible, but not fall-proof). Expect: the stuck teleport puts it back next to the owner. Test owned by Task 5.

### Task 5: Movement — follow the owner, stuck teleport

- Produces: `BotController.OwnerPosition : Vector3?` (the host's avatar position, null when there is no host avatar).
